## 怎么记录

每一关写四行：**目标 / 命令 / 为什么这么写 / 坑**。
「为什么」比「命令」重要——换台机器、换个目录，命令可能变，思路不会。

### Level 0 → 1

- **目标**：登录并拿到下一关密码
- **命令**：
  ```bash
  ssh bandit0@bandit.labs.overthewire.org -p 2220
  # 密码：bandit0
  ls
  cat readme
  ```
- **为什么这么写**：ssh连接网站语法，-p 指示端口号
- **坑**：-p 端口别忘，注意@前面写正确的用户名，cat只读不编辑文件。

### Level 1 → 2

- **目标**：打开“-”文件拿密码
- **命令**：cat ./-
- **为什么这么写**：用cat时-会被视为命令中的特殊符号加上./路径符号就会变成正常的路径名
- **坑**：留意-开头的文件

### Level 2 → 3

- **目标**：打开名字含有空格的文件
- **命令**：cat ./'--spaces in this filename--'
- **为什么这么写**：./表明是路径，‘’表明是文件名
- **坑**：-还是会误读为特殊字符，没有‘’文件名的空格会被识别为特殊字符。

### Level 3 → 4

- **目标**：找到隐藏文件
- **命令**：cd inhere; ls -a; cat .hidden
- **为什么这么写**：蓝色字体标明是目录许cd进入，ls加-a参数可以看隐藏文件
- **坑**：.开头文件可直接打开，.上一级，..上两级

### Level 4 → 5

- **目标**：在一堆文件中找到含密码的文件
- **命令**：file ./-file*   # 再 cat 输出里标为 "ASCII text" 的那个
- **为什么这么写**：-file(题中文件名为字符前缀)找以‘-’开头的字符文件，*路径名展开（匹配任意长度字符），file本身只是接收展开后的多个路径参数逐个判断类型（最后输出路径）。
- **坑**：-还是会影响命令，别忘了

### Level 5 → 6

- **目标**：找到对应文件按种类，大小，可执行性。
- **命令**：find . -type f -size 1033c ! -executable -exec file {} \;
- **为什么这么写**：find 递归查找；`.` 是当前目录；`-type f` 限定普通文件；`-size 1033c` 表示 1033 字节；`! -executable` 排除可执行文件；`-exec file {} \;` 对每个结果执行 file 并输出路径。
- **坑**：注意.目录，1033后没c是错的，不加c默认是512字节块（会匹配到1033*512字节），\;是-exec末尾结束语法，必不可少。

### Level 6 → 7

- **目标**：透过用户和组找到密码
- **命令**：find / -user bandit7 -group bandit6 -size 33c -type f 2>/dev/null
- **为什么这么写**：涉及用户和组全盘搜，从上级根目录搜，用户和组用对应英文做参数，2>/dev/null,2（文件描述符号）报错信息（与1正常结果输出对应）前面对应命令执行后的输出进行操作（整个），2>重定向错误输出，/dev/null 垃圾桶，>把输出重定向到想到达的地方。
- **坑**：注意/，写find不加目录会默认找当前目录，记得写对应目录

### Level 7 → 8

- **目标**：在一个txt文件里找到一个文本对应密码
- **命令**：grep millionth data.txt
- **为什么这么写**：查找文本对应字符串，-w整词搜索后接词语
- **坑**：-w严格对应整词，不加会变成字串匹配（串内有就输出）

### Level 8 → 9

- **目标**：文本中找到只出现过一次的字符串
- **命令**：sort data.txt | uniq -u
- **为什么这么写**：sort让所有行按字典序排，uniq对相邻行操作，-u找到没重复过的行，|是管道，放于两指令之间，左边输出作为右边输入。
- **坑**：uniq只能对相邻行比较，没sort提前排序无作用，|严格左右顺序 {uniq 不是“全局去重器”，它是“相邻段处理器”：一次只看上一行和当前行，相同就合并计数，不同就切段输出。所以相同内容必须相邻，uniq 才认得出来；sort 的作用就是制造这种相邻。}

### Level 9 → 10

- **目标**：混合数据文件中提取文本
- **命令**：strings data.txt | grep '=='
- **为什么这么写**：strings可以筛选出可读字符串（默认积累长度大于等于4），grep搜索
- **坑**：strings筛选注意长度（-n N）N默认是4

### Level 10 → 11

- **目标**：解码base64
- **命令**：base64 -d data.txt
- **为什么这么写**：-d decode解码
- **坑**：没什么坑

### Level 11 → 12

- **目标**：文件有英文字母（A-Z / a-z）都被“旋转”了 13 个位置，需要把它转回来
- **命令**：cat data.txt | tr 'A-Za-z' 'N-ZA-Mn-za-m'
- **为什么这么写**：tr字符转换工具（进位工具）'A-Za-z'原字符，'N-ZA-Mn-za-m'换后字符
- {典型ROT13编码，编两次恰好复原（26个字母）}
- **坑**：tr 只能通过标准输入（stdin）接收数据，不能直接把文件名作为参数传给 tr。所以必须用 cat data.txt | tr ... 或 tr ... < data.txt 的写法。
  
### Level 12 → 13

- **目标**：把十六进制转储还原成二进制，然后不断解压
- **命令**：1） head data.txt（看文件开头）
-           2） xxd -r data.txt > data.bin
-           3）gunzip data.gz ；bunzip2 data.bz2 ；tar xf data.tar ；file
-           4）mkdir  -p 地址（-p即没有目录就创目录）
- **为什么这么写**：解压工具只认字节流，不认十六进制文本，xxd 把字节转换成16进制文本，-r加上后就反过来；然后逐渐解压（后缀名不对就用mv改后缀名），文件扩展名不可靠，file看魔数{每种文件格式在文件开头固定位置有特定的字节序列，叫魔数。file 命令读文件头几个字节，和内置的魔数数据库比对，判断类型}
- **坑**：注意权限问题，一些目录只有读权限，没写权限，解压需要解权限，每一步得有严格的file判类型（家目录没权限）{
-r--------  1  bandit14  bandit14  ...
│││││││││
│└┴┴ 属主权限：r-- = 只读
│    属组权限：--- = 无权限
│    其他人权限：--- = 无权限
└ 普通文件}

### Level 13 → 14

- **目标**：利用私钥进入bandit14用户读密码
- **命令**：scp -P 2220 bandit13@bandit.labs.overthewire.org:~/sshkey.private .
-           chmod 600 sshkey.private
-           ssh -i sshkey.private bandit14@bandit.labs.overthewire.org -p 2220
- **为什么这么写**：scp基于ssh的远程文件复制，多用于上传和下载功能{下载：scp user@host:/远程/文件 本地路径；上传反过来}，ssh（获得密钥后）-i密钥登陆bandit14
- **坑**：一些服务器内不允许跨用户登录如bandit13->bandit14，scp端口参数严格大写（获得密钥后记得修改权限为只有所有者可读600，才能被ssh服务器许可使用；

### Level 14 → 15

- **目标**：利用14关的密码和服务器30000端口交互获得密码
- **命令**：echo 密码 |nc localhost 30000
- **为什么这么写**：echo自动化输入，nc（即ncat）发送请求到端口
- **坑**：记得端口号
